# طراحی معماری — سیستم OCR فارسی و انگلیسی
## (کلمات و جملات، دست‌نویس و چاپی، در سطح سند کامل)

نسخه ۱ — سند طراحی فنی پروژه (Phase 1)

---

## ۱. هدف پروژه

ساخت یک سیستم OCR کامل که بتواند از یک عکس سند واقعی (چند خط، فارسی و/یا انگلیسی، دست‌نویس یا چاپی) متن را استخراج کند و خروجی ساختارمند (JSON/CSV) بدهد. برخلاف طبقه‌بندی تک‌رقمی، این سیستم باید رشته‌های متن با طول متغیر را تشخیص دهد.

## ۲. تفاوت کلیدی با پروژه ارقام

| | پروژه ارقام (قبلی) | پروژه متن (این پروژه) |
|---|---|---|
| خروجی مدل | یکی از ۱۰ کلاس ثابت | رشته‌ای با طول متغیر |
| Loss | Sparse Categorical Crossentropy | CTC Loss |
| معماری | CNN ساده (Conv+Dense) | CRNN (CNN + BiLSTM) + CTC |
| جداسازی کاراکترها | Flood Fill دستی | نیازی به جداسازی تک‌کاراکتر نیست؛ کل خط با هم تشخیص داده می‌شود |
| ورودی مدل | تصویر ثابت ۳۲×۳۲ | تصویر با ارتفاع ثابت، عرض متغیر |

## ۳. مجموعه کاراکترها (Charset)

مدل باید این مجموعه را پوشش دهد (توکن CTC blank جداگانه اضافه می‌شود):

- حروف فارسی (۳۲ حرف، با در نظر گرفتن شکل‌های مختلف چون تشخیص در سطح تصویر است نه فونت، نیازی به تفکیک شکل ابتدایی/وسطی/پایانی در charset نیست — این را CNN از روی تصویر یاد می‌گیرد)
- ارقام فارسی: ۰۱۲۳۴۵۶۷۸۹
- حروف انگلیسی: a-z, A-Z
- ارقام انگلیسی: 0-9
- علائم نگارشی رایج: `. , ! ? : ; - ( ) " ' /` و فاصله (space)
- توکن ویژه CTC: blank

مجموع تقریباً ۱۱۰-۱۲۰ کلاس کاراکتر.

## ۴. نگاشت دیتاست‌ها به بخش‌های پروژه

| ترکیب | دیتاست اصلی | نوع | حجم قابل استفاده |
|---|---|---|---|
| فارسی چاپی | IDPL-PFOD2 (از GitHub می‌گیرم) | خط چاپی، برچسب واقعی | زیرمجموعه‌ای از ۲ میلیون تصویر |
| فارسی چاپی (مکمل) | Persian OCR Fonts (کگل) | خط/کلمه چاپی | تکمیلی |
| فارسی دست‌نویس | Arabic/Persian Handwritten Cities (کگل) | کلمه دست‌نویس واقعی | محدود، تکمیل با سینتتیک |
| فارسی دست‌نویس (تکمیلی) | تولید مصنوعی با فونت‌های شبه‌دست‌خط فارسی | خط سینتتیک | حجم دلخواه |
| انگلیسی دست‌نویس | IAM Handwriting Database | خط/کلمه دست‌نویس واقعی | ۱۳٬۳۵۳ خط |
| انگلیسی چاپی | تولید مصنوعی با فونت‌های لاتین (+ ۲۰k Synthetic OCR کگل به عنوان مکمل) | خط چاپی سینتتیک | حجم دلخواه |

همه‌ی این‌ها در مرحله ۲ به یک فرمت مشترک تبدیل می‌شوند: `(image_path, text_label, script, is_handwritten)`

## ۵. پایپ‌لاین کلی سیستم

```
عکس سند کامل (ورودی)
        │
        ▼
۱. پیش‌پردازش تصویر
   (خاکستری‌سازی، حذف نویز، deskew، باینری‌سازی تطبیقی)
        │
        ▼
۲. جداسازی خطوط متن
   (Projection Profile روی سند کامل → مختصات هر خط)
        │
        ▼
۳. برای هر خط: نرمال‌سازی
   (ارتفاع ثابت مثلاً ۳۲ یا ۶۴ پیکسل، عرض متناسب حفظ می‌شود)
        │
        ▼
۴. مدل CRNN + CTC
   (تشخیص رشته متن هر خط، مستقل از طول آن)
        │
        ▼
۵. CTC Decoding
   (Greedy یا Beam Search → تبدیل خروجی مدل به متن نهایی)
        │
        ▼
۶. بازسازی سند + خروجی ساختارمند
   (پیوند خط‌ها به ترتیب صحیح → JSON / CSV)
```

این دقیقاً همان ۴ مرحله‌ای است که در متن سایت خودتان توضیح داده‌اید (پیش‌پردازش → تشخیص ناحیه متن → تشخیص کاراکتر → خروجی ساختارمند)، با این تفاوت که این‌بار «تشخیص ناحیه متن» در سطح خط انجام می‌شود و «تشخیص کاراکتر» با یک مدل دنباله‌ای (CRNN+CTC) به‌جای طبقه‌بند تکی جایگزین می‌شود.

## ۶. معماری مدل (CRNN + CTC)

چند مدل برای مقایسه می‌سازیم (model_a, model_b, model_c) با این ساختار پایه:

```
Input: (height=32, width=None, channels=1)
        │
   Conv2D(64, 3x3) + ReLU + MaxPool(2,2)
   Conv2D(128, 3x3) + ReLU + MaxPool(2,2)
   Conv2D(256, 3x3) + BatchNorm + ReLU
   Conv2D(256, 3x3) + ReLU + MaxPool((2,1))   # فقط ارتفاع کم می‌شود، عرض حفظ می‌شود
   Conv2D(512, 3x3) + BatchNorm + ReLU
   Conv2D(512, 3x3) + BatchNorm + ReLU + MaxPool((2,1))
   Conv2D(512, 2x2) + ReLU                     # ارتفاع نهایی = 1
        │
   Reshape → (width', 512)   # دنباله ویژگی برای هر ستون از تصویر
        │
   Bidirectional LSTM(256, return_sequences=True)
   Bidirectional LSTM(256, return_sequences=True)
        │
   Dense(num_classes + 1)   # +1 برای CTC blank
        │
   CTC Loss (در آموزش) / CTC Decode (در inference)
```

نسخه‌های ساده‌تر (model_b با یک لایه BiLSTM، model_c بدون BatchNorm) هم برای مقایسه دقت/سرعت ساخته می‌شوند — دقیقاً مثل الگوی model1/model2/model3 در پروژه ارقام شما.

**تصمیم مهم:** یک مدل مشترک برای هر دو زبان آموزش می‌دهیم (charset ترکیبی)، نه دو مدل جدا. این باعث می‌شود سیستم بتواند سندهای دوزبانه را هم بدون نیاز به تشخیص زبان از قبل پردازش کند — دقیقاً چیزی که در نتایج فنی سایت‌تان هم قول داده‌اید («پشتیبانی از فارسی، انگلیسی و اسناد دوزبانه»).

## ۷. استراتژی آموزش

- Batch size: ۳۲ تا ۶۴ (به‌خاطر عرض متغیر تصاویر، از padding + بردار طول واقعی هر نمونه استفاده می‌شود)
- Callbacks: `ModelCheckpoint(monitor='val_loss', save_best_only=True)` و `EarlyStopping(patience=15)` — همان الگوی خودتان
- Optimizer: Adam
- معیار پایش: CER در validation (نه فقط loss)

## ۸. ارزیابی

- **CER** (Character Error Rate) — معیار اصلی
- **WER** (Word Error Rate) — معیار ثانویه
- ارزیابی جداگانه برای هر یک از ۴ ترکیب (فا-دست‌نویس، فا-چاپی، انگ-دست‌نویس، انگ-چاپی) تا مشخص شود مدل در کدام ضعیف‌تر است
